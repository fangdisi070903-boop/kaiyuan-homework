## 一页纸填写

| 要填的五项 | 本项目填写 | 为什么先定它 |

| 客户是谁 | 高校在校生与应届毕业生（求职群体），由高校就业指导中心 / 求职辅导机构牵头 | 决定报价模式与谈判对象（B 端学校/机构，还是 C 端学生） |

| 每天多少量 | 求职旺季日均约 80 次简历诊断请求（月均约 1,800 次），非旺季日均约 20 次 | Token 与算力测算的起点 |
| 数据在哪 | 简历文件由用户在前端上传，后端临时处理后即删、不持久化；大模型推理能力调用云端 API | 决定数据与对接工作量 |
| 能不能上云 | 简历含个人敏感信息，需在本地脱敏（去除姓名、电话、身份证号、邮箱等）后再调用云端大模型 API → **脱敏后可上云** | 一票否决项：决定 API 还是私有化 |

## 关键结论

1. **上云决策**：因简历含个人敏感信息，不能明文直接上云，必须在本地完成脱敏后再调用云端大模型 API，走 **API 模式**，暂不做完全私有化部署。
2. **算力测算起点**：按求职旺季日均 80 次请求估算 Token 消耗，作为后续大模型选型（上下文窗口、单价）与成本估算的依据。
3. **数据策略**：简历处理后即删、不持久化，降低数据合规风险与系统对接工作量。
