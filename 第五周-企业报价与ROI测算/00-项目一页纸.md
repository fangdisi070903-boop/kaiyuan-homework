# 00 项目一页纸

> 课程要求：自选项目开课前先填《项目一页纸》，五项不定，Token、服务器、ROI 全部算不准。
> 本项目沿用已完成的课程项目「出院随访与患者协作 业务挖掘」（仓库 `fangdisi070903-boop/ai-homework`）的真实设定，医院与数据均为虚构。

| 要填的五项 | 本项目填写 | 为什么先定它 |
| --- | --- | --- |
| **客户是谁** | 清禾综合医院（虚构，二级甲等，1,200 床），**医务部（随访中心）牵头**，质控办考核，信息科配合 | 决定报价模式与谈判对象：预算由医务部批，数据授权在信息科，合规否决权在质控办 |
| **多少人用** | 试点 2 科室（心内科、呼吸内科）：随访护士 14 人、医生 42 人、管理员 2 人；患者端 320 人次/月 | 决定并发与服务口径：峰值 8 路并发、日峰约 60 次请求 |
| **每天多少量** | 月随访 320 例 + 知识问答 680 次 = **1,000 次/月**（日均约 33 次） | Token 与算力测算的起点：月 Token 约 1,437 万 |
| **数据在哪** | HIS / EMR / 随访系统在**内网**，含姓名、电话、住院号等患者标识；知识库为院内制度与病种指导 | 决定数据与对接工作量：只读视图 2 个，需脱敏网关 |
| **能不能上云** | **患者原始数据不出内网**（医疗合规一票否决）；脱敏后的制度文本与匿名摘要可调云端 API | 一票否决项：排除纯云端 API，最终选**混合部署** |

## 与「青禾报销助手」底本的区别

| 维度 | 青禾底本 | 本项目 |
| --- | --- | --- |
| 行业 | 制造业财务报销 | 医疗随访 |
| 月业务量 | 2,400 张报销单 | 320 例随访 + 680 次问答 |
| 数据合规 | 脱敏后可调云端 API | 原始患者数据不得出内网，只能传脱敏文本 |
| 单次 Token | 输入 6,500 / 输出 900 | 随访 Agent 同为 6,500 / 900；问答 3,000 / 600 |
| 报告预算 | 教学案例 | 医务部已批 3 个月试点、8 万元（见 01 §4.2） |
